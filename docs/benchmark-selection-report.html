Benchmark Selection Report · 基准选型报告

IQRadar 基准选型报告：用哪几个 Benchmark 测大模型的"智商"

回答三个问题：当前五个基准（DeepSWE / SWE-Bench Pro / Terminal-Bench / GPQA Diamond / AIME 2024）为什么被选中； 它们各自在测什么能力；要更全面地刻画大模型"智商"，还应该补哪些基准。

1摘要

三句话读完全文。

① 现有五个基准选得对吗？
方向正确：它们用最低的落地成本覆盖了编码工程、工具执行、科学知识、数学推理四条主线，还兼顾了离线可跑、可信来源和抗污染。但它们缺了"智商"里最关键的一块——抽象/流体推理（fluid reasoning），且知识维度只有一个 GPQA。
② 这五者各在测什么？
DeepSWE（原创长程工程任务）、SWE-Bench Pro（企业级真实仓库修 bug）、Terminal-Bench（命令行工具使用）测“动手做事”的智能；GPQA Diamond（博士级科学）测知识深度；AIME 2024（竞赛数学）测数学推理。合起来是“能干活 + 有知识 + 会推理”，确实是一个合理的 IQ 雷达雏形。
③ 还有更合适的吗？
有。最值得补的是 ARC-AGI-2（抽象推理，最接近人类 IQ 测试的流体智力项），其次是 MMLU-Pro（知识广度）、HLE（顶级难点，防触碰天花板）、MATH-500/Putnam（数学难度梯度）、LiveCodeBench（竞赛代码）、GAIA（通用助手），并以 SWE-bench Verified 作校准锚点。详见第 6–7 节。

2先定义问题：大模型的"智商"由哪些维度构成

没有单一基准能测"智商"；IQ 是复合概念，评测组合必须先定维度。

人类 IQ 测试（如韦氏、瑞文渐进矩阵）测的是流体智力（抽象推理、模式识别、归纳）与晶体智力（知识、词汇）。迁移到大模型，"智商"至少应覆盖六个正交能力维度：

  1. 知识广度与深度（晶体智力）——通识/专业知识的存量：MMLU-Pro、GPQA Diamond、HLE。
  2. 数学与形式推理——符号操作、多步演绎、竞赛数学：AIME、MATH-500、HMMT/Putnam、FrontierMath。
  3. 抽象与流体推理（最像"IQ 题"）——在未见过的模式中做归纳与演绎，瑞文矩阵的机器版：ARC-AGI-1/2、Raven 数据集。
  4. 编码与工程智能（agentic coding）——读仓库、定位问题、改代码、跑测试：DeepSWE、SWE-Bench Verified/Pro、LiveCodeBench。
  5. 工具与交互执行——终端、浏览器、API 调用等真实环境中的多步操作：Terminal-Bench、GAIA、WebArena。
  6. 通用助手与鲁棒性——指令跟随、长上下文、检索型任务、少样本泛化：GAIA、RULER、IFBench 等。

一份好的评测组合 = 每个维度至少有一个基准 + 每个基准都有难度梯度（易→极难），才能在模型能力快速上涨时不至于集体封顶（饱和）。

3为什么选中这五个基准

选型时隐含了三条原则，五个基准恰好是这三条原则的最优交集。

原则一：维度互补，不重复考同一件事
5 个基准分别押在 4 个不同维度上（编码×2 偏重复、知识、数学、工具），彼此几乎没有重叠，雷达图能画出形状而不是一根柱子。
原则二：在 IQRadar 架构里"跑得动"
DeepSWE / SWE-Bench Pro / Terminal-Bench 走 Docker + Pier 的 agent 管线；GPQA / AIME 走无 Docker 的 api-eval 管线（直连 Bifrost 网关逐题打分）。国内网络下镜像走 registry-mirrors、数据集走 hf-mirror，全部离线可复现。
原则三：可信、权威、抗污染
五个都来自公认机构（Datacurve / ScaleAI / Terminal-Bench 团队 / Idavidrein / AIME 竞赛），题目多为短答或执行验证（选择/整数/测试用例），客观可判分，难以"糊弄"；DeepSWE 为原创任务，天然抗泄露。
DeepSWE Docker · Pier agent 管线 原创 · 长程 难度 ★★★★★

它是什么

Datacurve 出品的原创、长程（long-horizon）真实工程任务基准（datacurve-ai/deep-swe）：从真实开源仓库提炼的原始开发任务，周期长、步骤多，用来衡量"前沿编码 agent"而非被训练集污染的已知 issue。

测什么维度

维度 4（编码与工程智能）的高难长程端：仓库理解、多文件改动、自我验证、长时间自主执行。

为什么选它（对 IQRadar 的价值）
• 题目原创，几乎无泄露/刷分风险，是"智商"里最干净的增量信息；
• 项目本身就是围绕 DeepSWE + Pier 建的，跑通成本最低，天然是组合里的"主基准"；
• 长程任务的耗时/步数/成本本身也是智能密度的体现。
短板 / 注意
成本高（单任务可达千万级 token）；当前模型通过率普遍偏低，区分度集中在模型“会不会做事”而非“聪明多少”；任务量有限，样本量需注意。
SWE-Bench Pro Docker · SweAP 镜像 ScaleAI 出品 难度 ★★★★☆

它是什么

ScaleAI 在 2025 年发布的下一代软件工程基准：从约 177 个真实代码库中挑出比 SWE-bench Verified 难约 3 倍的任务（Pro 子集约 500 例，Pro-OS 全量约 3,000 例），仓库规模 2.5 万行以上，构造了接近真实工程环境的 Docker 环境。

测什么维度

维度 4 的企业级工程端：在大仓库中定位问题、跨模块修改、跑真实工具链验证。

为什么选它
• 与 DeepSWE 互补：一个偏“原创长程”，一个偏“真实仓库规模与工程复现”；
• 公认可信的参照系（SWE-bench 家族的 Pro 版），外部榜单可比性高；
• 与 Verified 之间巨大的分数差（发布时最强模型仅约 10–20%，2026 年上升到约 50%±），是当下区分度最好的 SWE 基准之一。
短板
镜像体积大、单任务成本高；分数随模型季度更新变动快（这是好事也是噪声）；若只跑少量样本，统计噪声明显。
Terminal-Bench Docker · tb CLI 真实终端环境 难度 ★★★★☆

它是什么

面向终端/命令行 agent的基准：在真实 Docker 容器里让模型完成系统管理、脚本编写、CLI 工具使用等任务（本项目固定使用 0.2.x 布局的 original-tasks，共 241 个任务）。2026 年发布的 v2.1 是其新一代版本，已被 Artificial Analysis 的智能指数采用。

测什么维度

维度 5（工具与交互执行）——目前五个基准里唯一测"在真实环境里操作工具"的项，恰好补上 DeepSWE/Pro 之外的动手能力。

为什么选它
• 真实环境判分（任务完成即通过），不是嘴炮式问答，衡量"执行智能"；
• 与编码 agent 正交：编码强 ≠ 终端会用，反之亦然，是雷达图的重要展开轴；
• tb CLI 成熟、可离线跑，镜像可预构建（项目已有 prewarm 支持）。
短板
环境/CLI 版本敏感，0.2.x 与 v2.x 不兼容（本项目已踩过坑）；多数模型通过率仍偏低，天花板低意味着对"智商上限"的区分有限。
GPQA Diamond api-eval · 无 Docker Idavidrein 出品 难度 ★★★☆☆（渐饱和）

它是什么

由博士级专家出题、198 道研究生水平的科学四选一题（生物/化学/物理），其中 Diamond 子集是专家一致同意度最高的部分，被称为"PhD-Level 科学基准"。题目难到非专家几乎不能答对，但模型可以在 0.9 以上。

测什么维度

维度 1（知识深度/晶体智力）——专门的深度知识项，五个基准里唯一的"知识"来源。

为什么选它
• 极低成本（198 题 × 单次调用，api-eval 直连网关，无 Docker 无子进程）；
• 判分客观、题库稳定，是各家榜单标配，可比性好；
• hf-mirror 上有免认证镜像，离线/受限网络可跑。
短板
头部模型已逼近 ~85–90%，接近饱和，对最强模型的区分度下降——这正是需要 HLE 之类更难的"知识题"的原因；且只覆盖三个理科，缺人文社科等知识广度。
AIME 2024 api-eval · 无 Docker 官方竞赛题 难度 ★★★☆☆（渐饱和）

它是什么

美国数学邀请赛（American Invitational Mathematics Examination）2024 年的30 道真题（I 卷 + II 卷各 15 题），答案是 0–999 的整数。竞赛数学推理的行业标准基准，被几乎所有模型卡与论文用作数学能力锚点。

测什么维度

维度 2（数学与形式推理）——多步推理、组合/数论/几何代数的综合运用。

为什么选它
• 官方真题、判分客观（整数答案），无裁判 LLM 的主观性；
• 成本极低（30 题），几十秒到几分钟即可出一组分数；
• HuggingFaceH4/aime_2024 免认证可直接准备成本地 JSONL。
短板
深度推理型前沿模型（o 系列、R1 级别）已接近满分，基本饱和；30 题样本小，Wilson 区间宽（±8% 量级），单次分数不宜过度解读。

5现有组合的缺口：为什么还"不够测智商"

不是五个选得不好，而是五个还不够——尤其是当你真的想量化"智商"这个上限指标。

缺口 1：没有抽象/流体推理项 —— 这是最像"IQ 题"的维度

人类 IQ 测试的核心是瑞文渐进矩阵式的抽象模式推理。现有五个基准全部是"知识/代码/数学"类，没有任何一项测"从未见过的抽象任务上即时归纳"。这在能力维度上是一个整块空白。

缺口 2：知识维度只有单点，且正趋饱和

GPQA Diamond 只覆盖三个理科的博士级知识，头部模型已 85%+。既缺人文社科/工程通识（广度），又缺更难的题库（上限），模型的"知识天花板"测不出来。

缺口 3：数学只有竞赛级单点，上下都缺梯度

AIME 对最强模型已接近满分（饱和），又缺少比 AIME 更难的数学（HMMT/Putnam/FrontierMath）和更便宜的低端基线（MATH-500）——难度没有梯度，曲线画不完整。

缺口 4：编码偏"修 bug"，缺"从零写算法"的纯推理编码

DeepSWE/Pro 都是仓库内改代码（定位→修改→测试），没有测算法设计与 competitive 编程这类更"烧脑"的纯推理编码（LiveCodeBench 恰好补这个）。

缺口 5：agent 能力缺"通用助手"场景

Terminal-Bench 只覆盖终端。浏览器、知识检索、多工具编排等通用 agent 任务（GAIA）缺席，导致"会不会用一般工具干一般活"测不到。

缺口 6：缺一个"校准锚点"

SWE-bench Verified 虽然逐年接近饱和，但它是全行业引用最广的 SWE 参照系。有一个 Verified 分数，外部可比性和"Pro 相对 Verified 的悬崖"都能直观呈现。

7推荐组合与落地节奏

分三个阶段推进：先跑零成本增量，再补 Docker 锚点，最后做重基建项。括号内为预估投入（按单模型、收敛样本估算）。

Phase 1 · 本周可做（低代码）补齐“智商”最缺的两根轴
  • 接入 ARC-AGI-2：自建渲染（题目 JSON → 输入栅格 → 模型输出栅格 → 判分），数十题即可看形状（api-eval 新类型，预计 1–2 天）；
  • 接入 MMLU-Pro：沿用现有 api-eval 的 MCQ 判分，采样 500–1000 题（预计半天）；
  • 接入 MATH-500 与 HMMT/Putnam 子集：沿用 numeric 判分，把数学拉成低→中→高梯度（预计 1 天）。
Phase 2 · 两周内（中等代码）上限缓冲与行业锚点
  • HLE 子集（~300–500 题采样）：防止 GPQA 饱和后知识维度失去区分度（api-eval，预计 1 天）；
  • SWE-bench Verified：复用 SWE-bench Pro 的 SweAP 镜像/管线，把"Verified vs Pro"悬崖变成雷达图上的信息（预计 1–2 天 + 跑分成本）；
  • LiveCodeBench：搭判题器（沙箱编译/运行），逐步放开（预计 2–3 天）。
Phase 3 · 择机（重）真实世界 agent 与数学天花板
  • GAIA：需要检索/浏览器基础设施，适合在 agent 框架扩展后接入；
  • FrontierMath：走申请流程拿数据集，作为"数学不可能三角"的展示项。

成本提示（数量级）

api-eval 类（GPQA/AIME/MMLU-Pro/MATH-500/HLE）：每基准每模型几十到几百次调用，成本可忽略，是"高频降智雷达"的理想载荷。Docker agent 类（DeepSWE/Pro/Verified）：单任务可达数百万到千万 token，是"低频深度体检"载荷。建议保持现有节奏——api-eval 天天跑，Docker agent 按周跑。

8风险与统计口径注意事项

基准会老化、分数会通胀，选型报告需要把这些风险写进口径。

  • 饱和（saturation）与污染（contamination）是最大风险：AIME、GPQA 已被写进大量训练语料，前沿模型逐年逼近满分；新基准（ARC-AGI-2、HLE、DeepSWE）抗污染强但样本小。对策：每季度复核一遍各基准的头部分数，淘汰"集体 95%+"的项，补充难档；
  • 样本量决定置信区间：AIME 仅 30 题，Wilson 区间宽；发布打点前至少对每个基准×模型积累 30–100 个样本，并在大盘同时展示区间；
  • IQ 公式口径：IQ = pass_rate × 1.5（上限 150）目前是"单基准通过率的线性换算"。若扩到多基准组合，建议改为"分维度加权"，对极难基准（ARC-AGI-2、FrontierMath）给权重而非线性分，否则天花板基准永远拉低总分，反而失去引导意义；
  • 成本与配额：Docker 类基准单任务 token 消耗巨大（曾有单任务千万级 input），跑批前用预算预估脚本做额度检查；
  • 环境漂移：Terminal-Bench 的 0.2.x / v2.x 不兼容、SWE-Bench 镜像随 Docker Hub 更新漂移——固定镜像 tag 与任务版本，避免"分数变了其实是环境变了"；
  • 双口径发布：保持"运行完成 ≠ 上大盘"的显式发布边界，快照不可变，给每个快照打上"基准集版本号"，方便历史可比。
